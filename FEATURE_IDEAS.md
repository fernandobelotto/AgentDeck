# AgentDeck Feature Ideas

Generated by multi-agent analysis of the codebase on 2026-01-08.

---

## Tier 1: High Impact Features

### 1. Multi-Terminal Support Framework
**Category:** Terminal Integration
**Impact:** High

Create an abstract terminal adapter interface that decouples terminal control from Kitty-specific implementations. Support iTerm2, Alacritty, WezTerm, Ghostty, and Windows Terminal through pluggable adapters with capability detection and graceful fallbacks. Each adapter implements send-text, send-key, focus-window, and launch operations.

**Why:** Currently the biggest adoption blocker. Terminal focus is 100% Kitty-dependent. Opens plugin to much larger audience.

**Key Files:**
- `src/utils/terminal-focus.ts`
- `src/utils/kitty-remote.ts`

---

### 2. Session History & Export
**Category:** Analytics
**Impact:** High

Persist session metadata and usage statistics to a local SQLite/JSON database, enabling users to query historical data, export session reports (CSV/PDF), and view usage trends over time. Include session replay capability showing state transitions.

**Why:** Foundational feature that enables all other analytics features. Currently all data is ephemeral.

---

### 3. Cost Alert Thresholds & Notifications
**Category:** Monitoring
**Impact:** High

Implement configurable per-session and global cost limits with Stream Deck notifications when thresholds are exceeded (e.g., alert when daily session cost exceeds $5 or hourly rate exceeds $50/hr). Include email digest options for summaries.

**Why:** Immediate user value. The plugin already tracks costs but doesn't alert users to runaway spending.

---

### 4. Windows/Linux Platform Support
**Category:** Cross-Platform
**Impact:** High

**Windows:** Implement terminal control using WinAPI or PowerShell remoting for window focus, SendKeys via UI Automation, and Windows Terminal/PowerShell ISE detection.

**Linux:** Add support via xdotool (X11) and ydotool (Wayland) for window focusing and key sending. Follow XDG Base Directory specification.

**Why:** Enables the largest platform demographics currently locked out. Requires conditional compilation based on `process.platform`.

---

### 5. Event-Driven State Machine
**Category:** Architecture
**Impact:** High

Replace implicit state management with an explicit state machine that validates and logs state transitions. Prevent invalid transitions (e.g., `permission` → `disconnected` → `idle`) and track state change chains for debugging.

**Why:** Currently instance states are updated reactively without validation. State machine improves reliability and debuggability.

**Key Files:**
- `src/server/instance-manager.ts`
- `src/actions/claude-instance-action.ts`

---

### 6. Per-Instance Statistics Dashboard
**Category:** UI/UX
**Impact:** High

Create a dedicated statistics view in the Property Inspector showing token usage trends, cost per instance, and state distribution pie chart (X% idle, Y% running, etc.) for the selected instance.

**Why:** The `UsageStats` interface and `usage-tracker.ts` already track comprehensive metrics. A visual dashboard provides immediate insights.

**Key Files:**
- `src/server/usage-tracker.ts`
- `ui/claude-instance.html`

---

### 7. OpenAI/ChatGPT CLI Integration
**Category:** Integrations
**Impact:** High

Monitor and control OpenAI's command-line interface instances alongside Claude and Gemini, with unified state tracking and gesture control. Extend the `InstanceSource` type to include "openai" and create a ChatGPT-specific log scanner.

**Why:** OpenAI CLI has similar patterns. Architecture is already extensible via `InstanceSource`. Unlocks multi-provider AI workflows.

## Tier 2: Medium Impact Features

### 8. Customizable Gesture Mapping
**Category:** Interaction
**Impact:** Medium

Extend the `InteractionHandler` to support more complex gestures: triple-click, rapid-tap sequences, duration-based holds (short/medium/long). Make action handlers context-aware based on current state (e.g., hold in "permission" approves, hold in "running" kills).

Allow users to rebind gestures per state in the Property Inspector.

**Key Files:**
- `src/utils/interaction-handler.ts`
- `src/actions/claude-instance-action.ts`

---

### 9. Slack/Discord Webhook Notifications
**Category:** Notifications
**Impact:** Medium

Extend notifications beyond Stream Deck to Slack/Discord webhooks with formatted messages including session name, state change, token usage delta, and cost incurred. Include rich media support (icon embeds, formatted tables).

---

### 10. tmux/zellij Integration
**Category:** Terminal
**Impact:** Medium

Add automatic session detection and routing for terminal multiplexers (tmux, zellij, screen). When multiple Claude instances run in split panes, intelligently route focus/signals to the correct pane using multiplexer APIs.

Support project-folder-based session affinity and session switching shortcuts.

---

### 11. Customizable Icon Themes
**Category:** UI/UX
**Impact:** Medium

Allow users to choose between multiple icon color schemes (Claude orange, Gemini blue, dark mode variants) and animation intensities directly in the Property Inspector.

**Why:** Currently icon styles are hardcoded. Infrastructure exists with `CLAUDE_STATE_CONFIGS` and `GEMINI_STATE_CONFIGS`.

---

### 12. Usage Quotas & Budget Management
**Category:** Monitoring
**Impact:** Medium

Add support for project-level and time-window-based budgets (monthly, daily, hourly) with granular allocation rules. Display remaining budget on Stream Deck icon with color coding (green/yellow/red). Include warning states before quota exhaustion.

---

### 13. Git Branch Context Display
**Category:** Integrations
**Impact:** Medium

Extend `StatusMetadata` to include git branch name and repo context; display on Stream Deck with branch indicator color coding (blue=main, yellow=feature, red=hotfix patterns). Add `/instances?repo=owner/name` filtering endpoint for multi-repo workflows.

---

### 14. Hook System Plugin Architecture
**Category:** Extensibility
**Impact:** Medium

Create a hook provider abstraction allowing custom hook implementations beyond the built-in `status-reporter.sh`. Users define hooks in JSON config with custom state mappings, URL endpoints, and event filters.

Support hooks for custom notification systems, metrics collection, and third-party integrations.

**Key Files:**
- `hooks/status-reporter.sh`
- `hooks/hooks.json`

---

### 15. Health Check & Auto-Recovery
**Category:** Reliability
**Impact:** Medium

Implement circuit breaker pattern for WebSocket connection between Stream Deck plugin and status server. Add health checks that measure connection quality, track message delivery success rates, and implement graceful degradation (fallback to cached state displays if server unavailable).

---

## Tier 3: Quick Wins & Polish

### 16. VT Escape Sequence Standardization
**Category:** Terminal
**Impact:** Low
**Effort:** Low

Detect terminal capabilities at runtime (256-color, true-color, kitty-graphics protocol, OSC support) and adapt VT escape sequences dynamically. Standardize progress/status indicators across terminals with fallbacks.

**Why:** Best effort-to-impact ratio for improving cross-platform experience immediately.

---

### 17. State Transition History Panel
**Category:** UI/UX
**Impact:** Low
**Effort:** Low

Add a collapsible history section in the Property Inspector showing the last 5-10 state transitions with timestamps (e.g., "running → editing 2 min ago → running 30s ago").

---

### 18. Health Status Tooltips
**Category:** UI/UX
**Impact:** Low
**Effort:** Low

Enhance the health indicators (server/Kitty status dots) to show detailed tooltips on hover in the Property Inspector, including connection details, last sync time, and error messages.

---

### 19. Structured Logging Pipeline
**Category:** Reliability
**Impact:** Low
**Effort:** Medium

Replace scattered console.log calls with structured logging that streams events to a central log aggregator. Create a unified event pipeline with consistent schema, log levels, timestamps, and context fields.

---

### 20. Smart Instance Recommendations
**Category:** UI/UX
**Impact:** Low
**Effort:** Low

Automatically suggest or highlight the most frequently-used or most-recently-active instance when opening the Property Inspector. Add a "Last Used" button alongside the instance list.

## Architecture Insights

### Current Strengths
- Clean separation of concerns (actions, server, icons, utils)
- Sticky state preservation prevents UI flicker
- Multi-source support (Claude/Gemini) already baked in
- Type-safe WebSocket messaging
- Excellent animation infrastructure (12 FPS frame-based system)

### Key Extensibility Points
- `InstanceSource` type designed for additions
- WebSocket message types allow new types without refactoring
- Log scanner pattern ready for duplication
- Display mode system shows pattern for custom visualizations

### Files Most Likely to Extend
- `src/server/types.ts` - Add new message types and source types
- `src/server/status-server.ts` - Add new HTTP endpoints
- `src/utils/terminal-focus.ts` - Add terminal adapters
- `src/icons/icon-generator.ts` - Add custom display modes
